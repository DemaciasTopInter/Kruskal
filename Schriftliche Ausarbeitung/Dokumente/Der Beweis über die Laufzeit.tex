Was ich zeigen möchte, ist, dass die Laufzeit $O(E\log_2|V|)$ ist.
Besser kann sie nicht werden, da bereits das Sortieren der Kanten-Liste am Anfang eine Laufzeit von $O(E\log_2|E|)$ hat, was dasselbe ist wie $O(E\log_2|V|)$, da $|E| \le |V|^2$.
Ich zeige also, dass ich Union und Find $O(|E|)$ Mal aufrufe und diese wiederum eine Laufzeit von höchsten $O(\log|V|)$ haben.

Um jetzt den Aussagen über die Laufzeit zu treffen, muss ich, wie in Kapitel \ref{Algolean} beschrieben, den Algorithmus ein weiteres Mal definieren und dieses Mal als Prog.

\subsection{Erstes Herantasten}
Wie erklärt musste ich zunächst festgelegt, was die grundlegenden Funktionen sind, die ich zählen möchte und eine entsprechende Query definieren.
Ich habe dabei vorerst für die Union und die Find Funktion, also \KruskalupdateunionFind und \KruskalconnectedcomponentofunionFindofid, entschieden.

\begin{definition}[\Kruskalkruskalquery]
  Eine Query mit den Funktionen Find und Union, bei der Find den Rückgabetyp \Kruskalfound hat, welchen ich nachfolgend definiere.
\end{definition}
\begin{lstlisting}
inductive (.\Kruskalkruskalquery.) (nodeList : List node) : Type → Type _ where
  | find (uF : unionFind nodeList) (id : Nat) (h : ∃ x ∈ nodeList, x.id = id) : kruskal_query nodeList (found nodeList uF)
  | union (uF : unionFind nodeList) (x y : Nat) (h₁ : ∃ a ∈ uF.linkList, (fun a => a.nodeId = x ∧ a.ccId = x) a) (h₂ : ∃ a ∈ uF.linkList, (fun a => a.nodeId = y ∧ a.ccId = y) a) : kruskal_query nodeList (unionFind nodeList)
\end{lstlisting}

Da diese Funktionen nur deklariert aber nicht definiert sind, konnte ich als Rückgabetyp für Find nicht Nat benutzen, da ich in \Kruskalkruskal verwende,
dass es für das Ergebnis einen Zeiger gibt, der zum entsprechenden Knoten gehört und auf diesen zeigt.
Deshalb brauchte ich einen Typ, der diese Bedingung beinhaltet.

\begin{definition}[\Kruskalfound]
  Ein Typ, bestehend aus einer ID und dem Nachweis, dass es einen Zeiger gibt, der diese als nodeId und als ccId hat.
\end{definition}
\begin{lstlisting}
structure (.\Kruskalfound.) (nodeList : List node) (uF : unionFind nodeList) : Type where
  mk ::
  id : Nat
  ex : ∃ (uFL : unionFindLink nodeList), uFL ∈ uF.linkList ∧ uFL.nodeId = id ∧ uFL.ccId = id
\end{lstlisting}

Da die Query nun definiert ist, kann ich nun den Kruskal Algorithmus als Programm dieser Query definierten.
Dabei war es mein Ziel den Aufbau so ähnlich wie möglich zu halten.

\begin{definition}[\Kruskalkruskalhelperprog]
  Die Prog-Version von \Kruskalkruskalhelper für die Query \Kruskalkruskalquery.
\end{definition}
\begin{lstlisting}
def (.\Kruskalkruskalhelperprog.) (edgeList : List edge) (nodeList : List node) (uF : unionFind nodeList) (edgesSoFar : List edge) (h_matching_edge : matching_edge edgeList nodeList) (h_nodup : nodeList.Nodup) : Prog (kruskal_query nodeList) (List edge) := do
  match edgeList with
  | [] => return edgesSoFar
  | e::es =>
    have h : ∃ x ∈ nodeList, x.id = e.node1 := by
      have h : (∃ x ∈ nodeList, e.node1 = x.id) → (∃ x ∈ nodeList, x.id = e.node1) := by simp [eq_comm]
      simp [h (h_matching_edge e List.mem_cons_self).left]
    let found_x : (found nodeList uF) ← kruskal_query.find uF e.node1 h
    let x := found_x.id
    have h' : ∃ x ∈ nodeList, x.id = e.node2 := by
      have h' : (∃ x ∈ nodeList, e.node2 = x.id) → (∃ x ∈ nodeList, x.id = e.node2) := by simp [eq_comm]
      simp [h' (h_matching_edge e List.mem_cons_self).right]
    let found_y : (found nodeList uF) ← kruskal_query.find uF e.node2 h'
    let y := found_y.id
    have h_matching_edge' : ∀ x ∈ es, (∃ y ∈ nodeList, x.node1 = y.id) ∧ ∃ z ∈ nodeList, x.node2 = z.id := by
      intro z h_in
      simp [h_matching_edge z (List.mem_cons_of_mem e h_in)]
    let updated_uF := ← kruskal_query.union uF x y found_x.ex found_y.ex
    let updated_edgesSoFar := update_edgesSoFar edgesSoFar e x y
    return ← kruskal_helper_prog es nodeList updated_uF updated_edgesSoFar h_matching_edge' h_nodup
\end{lstlisting}

\begin{definition}[\Kruskalkruskalprog]
  Die Prog-Version von \Kruskalkruskal für die Query \Kruskalkruskalquery.
\end{definition}
\begin{lstlisting}
def kruskal_prog (edgeList : List edge) (nodeList : List node) (h_matching_edge : matching_edge edgeList nodeList) (h_nodup : nodeList.Nodup) : Prog (kruskal_query nodeList) (List edge) := do
    let edgeListSorted : List edge := edgeList.mergeSort
    let uF : unionFind nodeList := init_unionFind nodeList h_nodup
    have h_matching_edge : matching_edge edgeListSorted nodeList := by
      intro e h_e_in
      simp [edgeListSorted] at h_e_in
      simp [matching_edge] at h_matching_edge
      exact h_matching_edge e h_e_in
    return ← kruskal_helper_prog edgeListSorted nodeList uF [] h_matching_edge h_nodup
\end{lstlisting}

\begin{lemma}[\KruskalkruskalhelpertimetwoindependentedgesSoFar]\label{KruskalkruskalhelpertimetwoindependentedgesSoFar}
  Die Laufzeit hängt nicht von der mitgeführten ErgebnisKantenListe ab.
  Für zwei verschiedene ErgebnisKantenListen kommt bei Laufzeitberechnung von \Kruskalkruskalhelperprog im Model \Kruskalkruskalmodeltwo also dasselbe raus.
\end{lemma}
\begin{proof}
  Den Beweis führe ich per Induktion über die Kanten-Liste.
  Im Basisfall wird keine der Funktionen aufgerufen.
  Im Induktionsschritt werden beide Funktionen auf beiden Seiten der Gleichung gleich oft aufgerufen, können also gestrichen werden.
  Danach greift dann schon die Induktionshypothese.
\end{proof}

Jetzt nutze ich aus, dass ich Union und Find separat zähle, und zeige die Laufzeit zunächst für Union, bevor im Anschluss dann die kombinierte Laufzeit kommt.

\begin{lemma}[\Kruskalkruskalhelpertimetworight]
  Wenn für eine natürliche Zahl n die Länge der Ergebnisliste von \Kruskalkruskalhelper kleiner ist als n,
  dann wird bei gleichem Input in \Kruskalkruskalhelperprog im Model \Kruskalkruskalmodeltwo Union höchstens n mal gezählt.

  Die Zahl n ist hierbei allgemein gehalten, gemeint ist aber die Anzahl der Knoten.
\end{lemma}
\begin{proof}
  Auch den Beweis führe ich per Induktion über die Kanten-Liste.
  Im Basisfall wird keine der Funktionen aufgerufen.
  Im Induktionsschritt gibt es eine erste Kante e und ich muss unterscheiden, ob die Knoten von e in derselben Zusammenhangskomponente liegen.
  Falls ja, wird e nicht aufgenommen und Union nicht gezählt.
  Die Aussage wird also von der Induktionshypothese abgedeckt.
  Falls nein, wird e in die ErgebnisKantenListe aufgenommen und Union gezählt.
  Sei nun n' eine Zahl, die um eins kleiner ist als n.
  Ich ersetze nun im Ziel n durch n' + 1.
  Dadurch kann ich auf beiden Seiten eins abziehen.
  In der Hypothese, dass die Länge der Ergebnisliste von \Kruskalkruskalhelper kleiner ist als n, ersetze ich n ebenfalls.
  Mit der Hilfe von Lemma \ref{KruskalkruskalhelperedgesSoFarappend} kann ich in der Hypothese ErgebnisKantenListe inklusive e aus der Funktion heraus holen.
  Die Länge [e] ist eins.
  Ich kann also auf beiden Seiten eins abziehen.
  Anschließend benutze ich das gleiche Lemma, um die ErgebnisKantenListe, dieses Mal ohne e, zurück in die Funktion zu stecken.
  Dadurch passt die Hypothese jetzt zu n', aber es fehlt jetzt e in der ErgebnisKantenListe.
  Nach Lemma \ref{KruskalkruskalhelpertimetwoindependentedgesSoFar} kann ich auch im Ziel e in der ErgebnisKantenListe loswerden.
  Damit passt es dann zur Hypothese und ich kann die Induktionshypothese anwenden.
\end{proof}

In den folgenden beiden Lemmata benutze ich für $|E|$ die Länge der Kanten-Liste, aber für $|V|$ die Anzahl der Knoten im SimpleGraph.\todo{warum}

\begin{lemma}[\Kruskalkruskalhelpertimetwo]
  \Kruskalkruskalhelperprog ruft im Model \Kruskalkruskalmodeltwo beim Ausführen Find höchstens $2|E|$ Mal auf und Union höchstens $|V|$ Mal.
\end{lemma}
\begin{proof}
  Sei n die Anzahl der Knoten, also die ID des höchsten Knotens plus eins.
  Ich muss die Aussage für beide Teile des Tupels zeigen.
  Für Union ist das genau die Aussage des vorherigen Lemmas.
  Für Find mache ich ebenfalls eine Induktion über die Kanten-Liste.
  Im Basisfall wird Find nicht aufgerufen.
  Im Induktionsschritt gibt es eine erste Kante und eine Restliste.
  Find wird zweimal aufgerufen, aber die doppelte Länge der Kanten-Liste ist auch zwei plus die doppelte Länge der Restliste.
  Ich kann also auf beiden Seiten zwei abziehen, dann greift die Induktionshypothese
\end{proof}

\end{lemma}

\subsection{Die tatsächliche Laufzeit}\todo{sub\-section 3 und find}

Bisher zähle ich die Aufrufe von Union und Find und verwende für beide den konstanten Wert eins.
Allerdings wird bei Union nur einmal etwas ersetzt, während Find sich immer wieder rekursiv selbst aufruft.

Dementsprechend sollte $\log_2|V|$ der wert von Find sein.
Bevor ich aber jetzt einfach ein weiteres Modell mit dem entsprechenden Wert schreibe, musste ich bedenken, dass der Beweis auf der strikten Rang-Invariante beruht.

\begin{lemma}[\KruskalconnectedcomponentofunionFindofunionFindLinkprogtimelog]
  Sei r der Rang eines beliebigen Zeigers uFL und gelte für die Union-Find-Struktur die strikte Rang-Invariante.
  Dann ruft für uFL \KruskalconnectedcomponentofunionFindofunionFindLinkprog im Model \Kruskalfindmodel beim Ausführen Parent höchstens $\log_2|V| - r$ Mal und Union gar nicht auf.
  Mit $|V|$ ist dabei die Länge der Knoten-Liste gemeint.
\end{lemma}
\begin{proof}
  Der Beweis erfolgt per Induktion über die Funktion \KruskalconnectedcomponentofunionFindofunionFindLinkprog.
  Im Basisfall zeigt der Zeiger auf seinen eigenen Knoten und keine der Funktionen wird aufgerufen.
  Im Induktionsschritt wird Parent einmal aufgerufen und für diesen Parent dann rekursiv \KruskalconnectedcomponentofunionFindofunionFindLinkprog.
  Sei s der Rang des Parents.
  Nach der Induktionshypothese wird Parent in diesem rekursiven Aufruf höchstens $\log_2|V| - r$ Mal aufgerufen.
  Dann muss also gezeigt werden, dass $1 + (\log_2|V| - s) \le \log_2|V| - r$ ist.
  Man könnte an dieser Stelle auf die Idee kommen, ist das der Fall, da $s \ge r$ ist, aber das reicht nicht ganz.
  Denn so wie Minus für natürliche Zahlen in Lean definiert ist, gilt für alle Zahlen a und b mit $a \le b$, dass $a - b = 0$.
  Das bedeutet, dass ich die 1 nicht einfach in die Klammer ziehen kann, denn $1 + (\log_2|V| - s) = (1 + \log_2|V|) - s$ gilt nur, falls $\log_2|V| \ge s$ ist.
  Deshalb ist die strikte Rang-Invariante vorausgesetzt, denn damit liefert mir Lemma \ref{Kruskalmaxrank} den entsprechenden Nachweis.
  Union kommt in der Funktion nicht vor, wird also auch nicht aufgerufen.
\end{proof}
